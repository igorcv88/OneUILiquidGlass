## Compositor contract and honest state

For Clear Glass, Fable §12 is preliminary; use the implementer's final names, domains and version handshake. Version support (such as a proposed optics version 12) means capability, not active clear material. Require confirmed compatible compiled HU/KG modes and generation, reliable radius/tag routing, and effective surface eligibility before activation.

| Evidence | Permitted state |
| --- | --- |
| Preference persisted | Saved/requested only |
| Property write acknowledged/read back | Property applied; shader state still unconfirmed |
| Fresh compatible compilation/status confirms matching values and generation | Compiled; still verify selected backend/tag per surface |
| Confirmed compiled mode plus live tag/backend match | Effective for the eligible surface; physical appearance still unverified |
| Changed compile-time flag/knob, stale/missing/failed acknowledgment | Pending recompilation or unknown; never applied-to-compositor |

The proposed modes are 0 baseline byte-identical, 1 clear for the whole profile requiring recompilation to switch, 2 both paths compiled with per-card tag selection. Only mode-2 per-card selection is live after compatible compilation is confirmed. Mode-2 baseline strength limits and clear slices must follow the contract and fp16 tests; do not allocate a fifth profile. Preserve baseline on unsupported versions, malformed/stale status, unreliable tags, old modules, APK-only and failed application. Do not silently initiate restart to resolve pending state.

Test independent HU/KG preferences across all combinations, persistence/restart, canceled or failed apply, stale generations and old app/new compositor compatibility. Never infer current device values from Tuning defaults or a library's advertised version alone.

## Ownership and restoration

Make an ownership table per surface/backend for backdrop sampling, refraction, native blur, fill/tint, structural Fresnel/contour/specular and dynamic `oulg_glow`. Confirm compositor ownership before disabling an existing fallback. Dynamic light must keep unrefracted source coordinates; region blur changes can affect its temporal stability. `kgsharedoptics` may cause duplicate contours in the baseline: record the alert and isolate any authorized fix rather than changing existing materials globally.

Capture/restore original ColorStateLists, backgrounds, native blur/tint/alpha/curve and drawable state through the existing lifecycle. Exercise disable, detach/rebind, eligibility loss, lock/unlock, popup→shade, failed capability, and returning from custom RemoteViews. Do not permanently clear native assets or overwrite content styling to make a screenshot look clear. Cover ordinary and customized notifications (including 99Food/Drogasil examples), actions, icons, text contrast, gestures and exit fades.

Keep shade/profile 2, QS/profile 3 (including PR #180), Now Bar, media, timer, Live Updates, shelf and toasts outside the material change unless explicitly requested. Preserve Theme Park and P3/HDR/Instagram paths and premultiplication. The mathematical spec's code conclusions [C] and Python results [N] do not establish on-device composition [P]; log-only draw markers are not visual acceptance.
